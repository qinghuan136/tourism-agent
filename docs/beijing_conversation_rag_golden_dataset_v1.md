# 北京游 Conversation RAG Golden Dataset v1

## 1. 数据集说明

- **语料范围**：当前数据库中的北京游 `41` 个 `retrieval_text` chunks。
- **Chunk ID**：直接使用截图中的行号 `1 ~ 41`。
- **目标用途**：
  1. 测 Retriever 的 `Hit@K / Recall@K / MRR`。
  2. 给 Reranker 生成真实候选集后，用 `relevant_chunk_ids` 自动形成正负标签。
  3. 辅助测定 Rerank relevance threshold。
  4. 测试旧事实失效、否定/例外、精确数字、语义改写、无答案等困难场景。
- **标注原则**：`relevant_chunk_ids` 只标记**能够直接提供回答证据**的 chunk，而不是所有“主题相关”的 chunk。
- 对于“**当前/最终**”类 Query，旧版本事实即使语义高度相关，也视为 **irrelevant / hard negative**。
- `[]` 表示历史中没有足够证据，正确行为应当是**不召回任何历史作为答案依据**。

> 注意：部分事实在后续 summary chunk 中会重复出现。本数据集优先保留最直接、最有判别力的证据；对于最终行程总结类 Query，则允许将 39~41 作为 relevant。

## 4. 建议的第一轮评测方式

### Retriever Recall / Hit

先关闭 Rerank 和 Threshold，只运行生产环境准备采用的前处理与 Retriever：

```text
Query
→ Query Rewrite（如果线上会启用）
→ Vector / Hybrid Retrieval
→ Top-K
```

建议记录：

- `Hit@5 / Hit@10 / Hit@20`
- `Recall@5 / Recall@10 / Recall@20`
- `MRR`

对于 `Q041 ~ Q050` 这类 `relevant_chunk_ids = []` 的样本，不参与普通 Recall 分母；单独用于后续 **No-answer / Threshold** 测试。

### Rerank Threshold

确定 `candidate_k` 后：

```text
每个 Query
→ Retriever Top-N 真实候选
→ 若 candidate_chunk_id ∈ relevant_chunk_ids，则 label=1
→ 否则 label=0
→ 固定 Reranker 打分
→ 扫描 threshold
→ 统计 Precision / Recall / F1
```

尤其关注这些困难样本：

- `Q005`：不喜欢早起 ≠ 所有早晨都禁止
- `Q009`：倾向智化寺 ≠ 已最终确认
- `Q015`：酒店价格高 ≠ 用户喜欢高价酒店
- `Q021`：10/3~10/6 是旧日期
- `Q022`：3500 是旧预算
- `Q026/Q028`：了解白塔寺 ≠ 加入白塔寺
- `Q030`：不喜欢排队 ≠ 顶级景点完全不排
- `Q035`：本次慢节奏 ≠ 永久旅行偏好
- `Q046`：喜欢夜间散步/夜景 ≠ 喜欢酒吧夜店
- `Q047`：愿意增加住宿预算 ≠ 必须五星酒店

## 5. 数据集统计

- Positive Queries：`40`
- No-answer Queries：`10`
- Total Queries：`50`
- No-answer 占比：`20%`
- 重点覆盖：
  - 用户偏好
  - 数字与日期
  - 条件与例外
  - 旧事实失效
  - 当前状态
  - 精确实体
  - “讨论/倾向/确认”状态区别
  - 局部偏好 vs 长期偏好
  - Hard Negative
  - No-answer
